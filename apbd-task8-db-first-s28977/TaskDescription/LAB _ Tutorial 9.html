Practical Task: REST API with EF Core Database First

In this exercise you build an ASP.NET Core Web API on top of an existing SQL Server database. The database schema is the source of truth, and EF Core classes are generated with the Database First workflow.

Business Context

A university already has a SQL Server database used to track students, courses, enrollments, assignments, and submitted solutions. Your team is asked to build a new REST API for this existing database. You are not starting from C# classes. You start from a database schema and use EF Core scaffolding to generate the initial model.

The task focuses on the topics from the lecture: Database First, scaffolding, generated code, partial classes, CRUD operations, LINQ queries, Include, AsNoTracking, Change Tracker, and integration with ASP.NET Core controllers.

Important: do not use EF Core migrations in this task. The database already exists. Schema changes are represented by SQL scripts, and the C# model is generated from the database.

Provided Database Script

Use the SQL script zadanie_1_db_first_university_tasks_setup.sql. It creates and seeds the database ApbdLecture9DbFirstTask.

The script creates five tables:

  • Students - student data, including index number and active status,
  • Courses - university courses,
  • Enrollments - relation between students and courses,
  • Assignments - assignments published for courses,
  • Submissions - submitted student solutions, scores, feedback, and status.

Run SQL Server in Docker

You may use your local SQL Server installation. If you want to run SQL Server in Docker, use this example:

If you use a local SQL Server installation, run the same SQL script in Azure Data Studio or SQL Server Management Studio.

Project Setup

Create an ASP.NET Core Web API project named UniversityTasksDbFirstApi. Use controllers, not Minimal API.

dotnet new webapi --use-controllers -n UniversityTasksDbFirstApi
cd UniversityTasksDbFirstApi
dotnet add package Microsoft.EntityFrameworkCore.SqlServer
dotnet add package Microsoft.EntityFrameworkCore.Design

If dotnet-ef is missing, install or update it:

dotnet tool install --global dotnet-ef
dotnet tool update --global dotnet-ef

Use this connection string in appsettings.json:

{
  "ConnectionStrings": {
    "DefaultConnection": "Server=localhost,14333;Database=ApbdLecture9DbFirstTask;User Id=sa;Password=YourStrongPassword123!;TrustServerCertificate=True"
  }
}

Scaffold the EF Core Model

Generate the context and entity classes from the existing database. The generated files should go into separate folders so it is clear which code came from scaffolding. 

dotnet ef dbcontext scaffold \
  "Server=localhost,14333;Database=ApbdLecture9DbFirstTask;User Id=sa;Password=YourStrongPassword123!;TrustServerCertificate=True" \
  Microsoft.EntityFrameworkCore.SqlServer \
  --context UniversityTasksDbContext \
  --context-dir Data \
  --output-dir Models \
  --no-onconfiguring

After scaffolding, register the generated context in Program.cs:

builder.Services.AddDbContext<UniversityTasksDbContext>(options =>
    options.UseSqlServer(builder.Configuration.GetConnectionString("DefaultConnection")));

builder.Services.AddControllers();
builder.Services.AddEndpointsApiExplorer();
builder.Services.AddSwaggerGen();

Do not edit generated files directly. EF Core generates partial classes. Your custom logic should be placed in separate files such as Student.Partial.cs or Assignment.Partial.cs.

Partial Class Requirements

Add your own logic without modifying scaffolded files.

Student.Partial.cs

  • Add a read-only property FullName returning first name and last name.
  • Add a method HasAcademicEmail() returning true when the email ends with @students.example.edu.
public partial class Student
{
    public string FullName => $"{FirstName} {LastName}";

    public bool HasAcademicEmail()
    {
        return Email.EndsWith("@students.example.edu", StringComparison.OrdinalIgnoreCase);
    }
}

Assignment.Partial.cs

  • Add a method IsOverdue(DateTime now).
  • The method should return true when DueDate is earlier than now.

DTO Requirements

Do not return scaffolded EF entities directly from controllers. Prepare DTOs for API responses and request bodies.

  • CourseDto - course id, code, name, credits, assignment count,
  • AssignmentDto - assignment id, title, due date, max points, published status, submission count,
  • StudentDashboardDto - student id, index number, full name, active status, enrollments, submissions,
  • SubmissionDto - submission id, student, assignment, repository URL, status, score, feedback,
  • CreateSubmissionDto - assignment id, student id, repository URL,
  • GradeSubmissionDto - score and feedback.

Endpoints to Implement

Method Endpoint Required logic GET /api/courses?activeOnly=true Return courses with assignment counts. Use AsNoTracking() and projection to DTO. GET /api/courses/{idCourse}/assignments?publishedOnly=true Return assignments for one course. Include submission count. Return 404 if the course does not exist. GET /api/students/{idStudent}/dashboard Return student details, enrollments, and submissions. Avoid the N+1 problem by using Include, ThenInclude, or projection. POST /api/submissions Create a new submission after checking business rules. PUT /api/submissions/{idSubmission}/grade Grade a submission. Demonstrate Change Tracker behavior by loading the entity, changing properties, and calling SaveChangesAsync(). DELETE /api/submissions/{idSubmission} Delete a submission only if it is not graded. Return 400 when the submission is already graded.

Business Rules

Create submission

  • The student must exist.
  • The student must be active.
  • The assignment must exist and be published.
  • The student must be enrolled in the course that owns the assignment with status Active or Completed.
  • The same student cannot submit the same assignment twice.
  • If the current time is after DueDate, set status to Late; otherwise set it to Submitted.
  • RepositoryUrl cannot be blank and should start with https://.

Grade submission

  • The submission must exist.
  • The score cannot be lower than 0.
  • The score cannot be higher than the assignment's MaxPoints.
  • After grading, set status to Graded.

Delete submission

  • The submission must exist.
  • A graded submission cannot be deleted.
  • Return 204 No Content after a successful delete.

EF Core Requirements

  • Use Database First scaffolding to generate entities and DbContext.
  • Do not use migrations in this task.
  • Do not edit scaffolded entity files directly.
  • Use partial classes for custom logic.
  • Use AsNoTracking() for read-only list queries.
  • Use Include, ThenInclude, or projection to avoid N+1 queries.
  • Use async EF Core methods such as ToListAsync(), FirstOrDefaultAsync(), AnyAsync(), and SaveChangesAsync().
  • Use DTOs instead of exposing EF entities directly.

Suggested Work Order

  1. Run SQL Server and execute zadanie_1_db_first_university_tasks_setup.sql.
  2. Create the ASP.NET Core Web API project with controllers.
  3. Add EF Core packages and the SQL Server provider.
  4. Run the scaffolding command and inspect generated files.
  5. Register UniversityTasksDbContext in dependency injection.
  6. Add DTOs and partial classes.
  7. Implement read endpoints first, using projections and AsNoTracking().
  8. Implement create, update, and delete endpoints.
  9. Test business-rule errors in Swagger or Postman.
  10. Run scaffolding again with --force only after you understand which files will be overwritten.

Completion Criteria

  • The database is created from the provided SQL script.
  • EF Core model classes are generated from the database by scaffolding.
  • The project does not use EF Core migrations.
  • Custom code is placed outside scaffolded files, for example in partial classes, DTOs, services, and controllers.
  • The API implements all required endpoints.
  • Read-only endpoints use AsNoTracking() where appropriate.
  • The student dashboard avoids the N+1 problem.
  • The API returns meaningful HTTP statuses: 200, 201, 204, 400, 404, and 409 where appropriate.

What This Task Practises

  • starting from an existing SQL Server database,
  • scaffolding EF Core entities and DbContext,
  • separating generated code from custom code,
  • using partial classes safely,
  • implementing CRUD operations with EF Core,
  • using Include, projections, and AsNoTracking(),
  • integrating EF Core with ASP.NET Core REST API controllers.
